PDF Downloads in Playwright
Overview
Playwright can automatically detect and download files generated by a web application. Instead of interacting with the browser's download dialog, Playwright listens for a download event and gives you access to the downloaded file.
This approach is reliable and works well for validating PDF reports.
________________________________________
Waiting for a Download
Always start waiting for the download before clicking the button that generates the PDF.
Example:
const downloadPromise = page.waitForEvent('download');

await reportsPage.downloadPdf();

const download = await downloadPromise;
This prevents Playwright from missing the download event.
________________________________________
Saving the Download
After the download completes, save it to a location that your test can access.
Example:
const filePath = path.join(downloadFolder, download.suggestedFilename());

await download.saveAs(filePath);
________________________________________
Using suggestedFilename()
Instead of creating your own filename with timestamps or random values, use:
download.suggestedFilename()
Benefits:
•	Uses the filename provided by the application.
•	Makes debugging easier.
•	Produces cleaner test output.
•	Avoids unnecessary naming logic.
________________________________________
Organizing Download Folders
Store downloaded files in a dedicated folder inside the project.
Example:
project/
│
├── data/
│   └── downloads/
│
├── tests/
├── pages/
└── helpers/
Keeping downloads in one location makes cleanup and debugging much easier.
________________________________________
Reading the PDF
After saving the file, pass the file path to your PDF parser.
Example:
const pdfText = await parsePdf(filePath);
The parsed text can then be used for assertions.
________________________________________
Common Workflow
Typical PDF download flow:
1.	Navigate to the report page.
2.	Populate report fields.
3.	Generate the report.
4.	Wait for the download event.
5.	Save the PDF.
6.	Parse the PDF.
7.	Validate the extracted values.
________________________________________
Common Mistakes
Waiting after clicking
❌ Incorrect
await reportsPage.downloadPdf();

const download = await page.waitForEvent('download');
The download may already have started, causing the test to fail.
________________________________________
Correct Order
✅
const downloadPromise = page.waitForEvent('download');

await reportsPage.downloadPdf();

const download = await downloadPromise;
________________________________________
Forgetting await
Missing await can cause Playwright to continue before the download finishes.
Always wait for:
•	waitForEvent()
•	saveAs()
•	Any asynchronous file operations
________________________________________
Incorrect File Paths
Use Node's path.join() instead of manually creating file paths.
Example:
const filePath = path.join(downloadFolder, download.suggestedFilename());
This works across different operating systems.
________________________________________
Hardcoding Filenames
Avoid:
"report.pdf"
Instead use:
download.suggestedFilename()
This makes the test more flexible if the application changes the filename.
________________________________________
Best Practices
•	Wait for the download before clicking.
•	Save PDFs using download.saveAs().
•	Use download.suggestedFilename().
•	Store downloads in a dedicated folder.
•	Parse the PDF after saving it.
•	Keep download logic separate from PDF parsing logic.

Notes from My Project
During this project I learned:
•	Always wait for the download event before clicking the download button.
•	Save the PDF to a known folder so it can be parsed later.
•	Use download.suggestedFilename() instead of manually creating filenames.
•	Keep PDF downloading and PDF parsing as separate responsibilities.
•	Verify the downloaded PDF by parsing its contents rather than only checking that a file exists.
